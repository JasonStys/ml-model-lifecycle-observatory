# Model release review

Author: Jason Stys. Intended user: an operator reviewing the repository's synthetic service-health classifiers before a separately authorized lifecycle decision.

1. Train/register candidates with the existing reproducible demo or pipeline, keeping content-addressed JSON bundles and registry together.
2. Run `python -m ml_observatory.cli review MODEL_ID --registry PATH --artifact-root PATH --report NEW.json`. Optional `--drift-report PATH` accepts bounded local JSON. Output must be new. No lifecycle/deployment/prediction command executes.
3. Check `verification_scope`: model bytes, manifest/schema and registry algorithm/dataset/evaluation metadata must agree. Declared dataset fingerprint is shown; raw dataset bytes and test metrics are **not independently reevaluated** (`dataset_bytes_verified:false`). Positive train/calibration/test counts are declarations, not independent proof of split integrity.
4. Review AUC≥0.68, subgroup recall gap≤0.40 and finite Brier, with probability-domain sanity bounds0–1. The first two thresholds match selection; the dossier adds explicit finite/domain checks. Failed gate names and full recorded subgroup metrics remain visible. Eligibility on recorded quality is descriptive, not promotion approval.
5. Review optional drift: model identity, all eight unique features, positive sample count, finite/nonnegative PSI, ordered thresholds and feature/overall levels must agree. Below100 samples gets a small-sample review flag. This heuristic is not statistical confidence. Missing evidence does not mean stable; drift does not prove accuracy changes or justify promotion.
6. Inspect one coherent SQLite snapshot of current roles and100 newest promotion-history entries with total/truncation flags. Prior rollback candidate is unverified context, and no rollback occurs. Other operators may change state after the snapshot.

The admin read endpoint `GET /v1/admin/models/{id}/review` requires the configured `X-Admin-Token`. Missing/wrong tokens return401, unknown models404 and unverifiable evidence409 with a generic message. It accepts no artifact/drift path parameters and omits registered filesystem paths. The snapshot uses SQLite read-only URI mode; a missing registry is not silently created. Existing `/docs` and CLI `review --help` explain use. This is a controlled synthetic lab, not a multi-user account platform or production release authority.

`src/ml_observatory/review.py` owns gate reasons, bounded artifact/context reads, metadata reconciliation and dossier assembly. `Registry.review_snapshot` reads metadata/roles/history in one transaction. `registry.py` now closes every schema/read connection explicitly: SQLite's context commits/rolls back but does not close handles. `api.py` provides an authenticated read; `cli.py` offers create-new JSON export. `tests/test_review.py` independently checks thresholds and actual trained-artifact/CLI/API journeys, no-write behavior, context errors, tamper/metadata rejection and bounded history. Existing95% coverage, audits, PostgreSQL, manifests and container gates remain enabled.
